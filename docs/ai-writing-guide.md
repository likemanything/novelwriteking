# 写作智能指南

给要修改提示词、审稿、台账、灵感相关代码的人（和 AI）。这份文档记录的是**做过实验、踩过坑之后**的结论。

## 1. 写作提示词的设计原则

`WRITER_SYSTEM`（`src/ai/prompts.ts`）围绕「手艺」而不是「要求」：

1. **忠实**：细纲的情节点必须真实发生；设定是事实；不擅自发明重大设定。
2. **场景手艺**：每个场景有「想要 → 阻力 → 局面改变」；进场晚、出场早；细纲是骨架不是清单（关键转折写足，过渡带过）；用视角人物的主观过滤来写。
3. **语言**：具体胜过抽象；比喻克制（全章 ≤ 4 处，不以比喻收尾）；不用套话；句式与段落有变化；对白带潜台词；情绪用动作与物件传达。
4. **收尾**：落在具体画面 / 动作 / 对白上，不总结、不点题、不复述细纲里的钩子。
5. **篇幅**：靠「把场景写透」达到，**不靠追加情节**——最后一个情节点与章末悬念就是本章的结尾。

### 实验得到的教训
- 给**硬性字数下限 + 逐情节点字数**会让带思考的模型陷入数字数，把整个额度花在思考上、什么都没写出来。只写「约 N 字」，并说明「篇幅靠写透场景」。
- 只说「宁可写足」会让模型在钩子之后追加「第二天」的场景来凑字数。必须同时说「最后一个情节点与章末悬念就是结尾」。
- 人物命名要有辨识度（避免「沈砚 / 沈砚舟」这类同姓近字），否则读者与连续性检查都会混淆。
- 要求「必须正好输出 N 章」，否则大纲经常少给。

## 2. 修改提示词的流程

1. **先定度量**。现成的：`lintProse`（比喻 / 千字、以比喻收尾的段落、套话）、字数、结尾是否停在钩子、情节点是否全部发生。
2. **固定夹具**：同一个灵感、同一份设定、同一章细纲，用真实模型各跑一次旧版与新版（同温度），比较度量与人工通读。把夹具存进 `sessionStorage`，因为改前端文件会热更新重载页面。
3. **一次只改一件事**，否则不知道是什么起了作用。
4. 改完把结论（数字 + 一句话原因）写进这份文档的「实验教训」。
5. 不要只在演示引擎上验证——它不是语言模型。

## 3. 额度、截断与「思考」

- 带思考的模型：思考 token 计入 `max_tokens`。额度不够会得到**空内容**或被截断的 JSON。
- 现行预算（`tasks.ts`）：开书 12000、大纲 16000、审稿 10000、台账 8000（失败重试 14000）、起草 `max(8000, 字数×3.2)`、灵感 6000。
- `call()` 的保护：
  - 结构化输出被截断 → 额度加倍重试一次；
  - 正文被截断 → 自动让模型接着写完（最多 2 次）；
  - 额度被思考耗尽（空内容）→ 加倍重试一次；
  - 服务商对 `max_tokens` 有更低上限（400）→ 自动降档（`providers.ts`）。
- 不要把预算调小来「省钱」而不看后果；要省，先看用量表。

## 4. 审稿：别信模型的「证据」

模型会编造引文，会把没写出来的情节点说成已完成。`verify.ts` 的做法是**程序核对，不是再问一遍模型**：

| 检查 | 规则 |
| --- | --- |
| 意见里的引文 | 精确 → 忽略标点 → 近似（字二元组 Dice ≥ 0.72）三级定位；找不到就丢弃，并在报告顶部告知数量 |
| 情节点「已完成」 | 引文必须能在正文找到，否则降为「待核实」 |
| 情节点「未完成」 | 正文已覆盖其 ≥ 60% 关键词时降为「待核实」 |
| 人名写串 | 与设定人物只差一字且出现 ≥ 2 次 → 程序直接报，不依赖模型 |
| 连续性冲突 | 必须同时给出正文原句与被违背的前文事实；原句核对不上整条丢弃 |

评分标准给了锚点（6 = 合格初稿，大多数初稿 5–7），界面标注「AI 评分仅供参考」。

**新增任何「模型判断」时**：同样要有程序核验与单元测试（`tests/ai.test.ts`）。

## 5. 连续性台账

- 每章「摘要 + 8–14 条原子事实」存在 `Chapter.digest`，由正文指纹（`hash`）判断是否过期。
- 起草与审稿前，`ensureDigestsBefore` 为前几章补齐（最多 6 章）；起草时前一章没定稿也一样。
- 生成台账时**同时对照前文事实**：与前文矛盾的内容放进 `digest.conflicts`，**不进 `facts`**——防止错误被当成正典污染后文。
- 作者在审稿面板点「这是有意为之」→ `acknowledgeConflict` 写入台账（伏笔、有意的时间错位等）。
- 台账失败（JSON 解析等）会重试一次；仍失败只记日志、不阻塞写作。
- 局限：只对照最近 6 章；需要多步推理（算年龄）才能发现的矛盾不一定抓得到。

## 6. 随机灵感

- 结构：质量标准 + 范例锚点 + **思维算子**（规则化、让常识反过来、社会推演、错位混搭、视角置换……）+ 随机种子（冷门职业 / 物件）+ 三档浓度（温情 / 奇想 / 大脑洞）+ 明确禁用的陈词（灯塔、邮差、当铺……）。
- 一次生成一批，按档缓存，后台预取；没模型时用本地「职业 × 带代价的规则」组合器。
- 教训：种子元素要写成「可借用、不自然就舍弃」，写成「必须出现」会让句子塞满元素；「一句话只放一个让人愣一下的点」。
- 被写烂的意象会随时间变化，定期用真实模型抽样检查，把新出现的套路加进禁用列表。

## 7. 文字体检（`lint.ts`）

确定性规则：比喻密度（像 / 仿佛 / 如同 …… 每千字）、以比喻收尾的段落占比、套话（一丝 / 不禁 / 深吸一口气 / 眼中闪过……）。少于 600 字不下结论。阈值保守——这是「兜底」，不是文学评价；真实模型的正常输出（4 / 千字）不应被误报。
