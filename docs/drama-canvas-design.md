# 墨织「小说 → 短剧」画布：产品设计

> 一部小说进去，一部可以发布的竖屏短剧出来。画布不是让用户从零搭管线，而是**一条开箱即用、每一步都可展开、可改、可重跑的流水线**。

## 1. 定位：为什么不是又一个 ComfyUI

通用节点画布给的是「零件」，用户要自己知道该连什么。墨织的画布给的是**答案**：

| 通用画布 | 墨织短剧画布 |
| --- | --- |
| 空白画布 + 节点库 | 导入小说即自动生成整张工作流，用户从"看结果"开始 |
| 节点是技术概念（采样器、VAE） | 节点是编剧/导演概念（分集、场景、分镜、角色定妆、配音） |
| 连线决定数据类型 | 连线表示"这一步的产出喂给下一步"，类型由系统保证，不会连错 |
| 出错看日志 | 每个节点能说清"我用了小说第几章哪几段、为什么这样改" |
| 一次性跑完 | 逐节点审批：AI 提议、作者确认，与墨织"作者把关"一脉相承 |

核心原则：**一致性第一**（人物脸、服装、场景跨镜头不漂移）、**成本可见**（跑之前先估价）、**可断点续跑**（视频生成慢且贵，失败不重来）。

## 2. 用户旅程

1. **选小说**：书架上任意一部（自己写的、平台生成的、导入的 .txt）。选章节范围。
2. **选剧型**：一句话预设——集数（20–80 集）、单集时长（60–120 秒）、画幅（9:16 / 16:9）、类型节奏（爽文反转 / 悬疑 / 甜宠 / 古风）、画风（真人感 / 国风动画 / 2D 漫画）。
3. **一键生成工作流**：画布自动铺开整条流水线，文本类节点（改编、剧本、分镜）用 DeepSeek 立即跑完；用户在**剧本阶段先审**，满意再放行视频生成。
4. **审与改**：点任意节点展开右侧检查器，改文字、换图、锁定、重跑单个节点；改动自动让下游标记"已过期"。
5. **估价与放行**：视频生成前弹出清单（镜头数 × 单价 = 预计费用），确认才开始。
6. **成片**：时间线预览，换镜头、调配音、导出 MP4 / 剪映草稿 / 分镜 PDF。

## 3. 流水线（默认工作流）

```
小说章节 ─▶ ① 故事拆解 ─▶ ② 分集大纲 ─▶ ③ 单集剧本 ─▶ ④ 分镜脚本 ─▶ ⑤ 镜头视频 ─▶ ⑥ 成片
              │                              ▲              ▲              ▲
              ▼                              │              │              │
         人物库/场景库 ─▶ ⑦ 角色定妆照 ─▶ 场景概念图 ───────┴──────────────┘
                                  配音/字幕/音乐 ─────────────────────────────▶
```

| 节点 | 输入 | 输出 | 模型 |
| --- | --- | --- | --- |
| ① 故事拆解 | 小说章节 + 设定集 | 主线/支线、关键事件、人物关系、"可视化程度"打分 | 文本（DeepSeek） |
| ② 分集大纲 | 拆解结果 + 剧型 | 每集：钩子、冲突、反转、**结尾悬念**（短剧生命线）、对应原著章节 | 文本 |
| ③ 单集剧本 | 分集大纲 + 人物声线 | 场景化剧本：对白精简、动作可拍、旁白可选 | 文本 |
| ④ 分镜脚本 | 剧本 | 镜头列表：景别、运镜、时长(3–8s)、画面描述、台词、首尾帧提示词 | 文本 |
| ⑦ 角色定妆 / 场景概念 | 人物设定 + 画风 | 每个角色的标准形象（正/侧/全身）、每个主场景一张定调图 | 图像模型 |
| ⑤ 镜头视频 | 分镜 + 角色/场景参考图 | 每镜头一段视频（图生视频，首帧 = 参考图拼合） | 视频模型 |
| ⑥ 成片 | 镜头视频 + 配音 + 字幕 | 单集时间线 → MP4 | 配音(TTS) + 本地合成 |

**节点分组**：画布按"集"折叠成泳道，一眼看到整部剧的进度；"人物库/场景库"是跨集共享的**资产节点**，改一次全剧生效。

## 4. 画布交互

- **无限画布**：缩放/平移，小地图；自动布局（默认从左到右、按集分行），用户可拖动但不必。
- **节点状态**（颜色 + 印章语言，延续墨织视觉）：待办、运行中（丝线流动）、待审、已通过（朱砂印）、过期（淡出虚线）、失败（可重试）。
- **连线即依赖**：改上游 → 下游自动"过期"，一键"重算过期节点"，只跑变化的部分。
- **逐节点审批**：文本节点可"自动通过"，视频节点默认"需确认"。
- **溯源**：剧本里每句旁标注"来自第 12 章 ¶3"，点击跳回小说原文——这是相对通用工具的差异化能力。
- **版本**：每个节点保留历史输出，可回退、可 A/B 对比（尤其是视频抽卡）。
- **高级模式**（默认隐藏）：允许插入自定义节点（提示词节点、人工上传节点、条件分支），给进阶用户留出 ComfyUI 式自由。

## 5. 一致性方案（质量成败所在）

1. **角色圣经**：定妆照 + 固定外观描述词，作为每个镜头的强制参考输入。
2. **场景圣经**：每个主场景一张定调图 + 光线/色调描述。
3. **画风锁**：全剧统一风格词与负面词，写入每个镜头提示词。
4. **首尾帧衔接**：相邻镜头用上一镜尾帧作下一镜首帧（视频模型支持时）。
5. **抽卡与锁定**：每镜头默认生成 1 条，可"再来 N 条"择优，选定即锁定。
6. **一致性检查节点**（后期）：用视觉模型比对镜头与定妆照，低分镜头提示重做。

## 6. 模型接入与成本

### 6.1 文本
复用墨织现有「AI 网关」：短剧的文本节点走「构思」环节分配的模型（如 DeepSeek），同一套密钥加密、额度与用量记录（用量环节记为 `drama`）。

### 6.2 视频 / 图像 / 配音：声明式「通用适配器」
目标：用户接入**任何**视频模型都不需要我们改代码。做法是不为每家写一个 SDK，而是用一份可校验的 JSON「适配声明」（`ProviderSpec`）描述一家服务怎么调用；系统内置若干家的预设，其余由用户填写、导入或由 AI 辅助生成。

```
ProviderSpec {
  kind: 'video' | 'image' | 'tts'
  baseUrl
  auth:  bearer | header | query | basic | jwt-hs256 | sigv4（覆盖绝大多数国内外厂商，含需要 AK/SK 签名的）
  capabilities: { modes: [t2v, i2v, first-last, ref-images], durations: [5,10], ratios, resolutions,
                  maxPromptChars, audio: native | none, seed, negativePrompt }
  submit: { method, path, headers, bodyTemplate, imageInput: url | base64 | multipart, taskIdPath }
  poll:   { method, path（含 {{task_id}}）, intervalSec, timeoutSec,
            statusPath, running[], success[], failed[], resultUrlPath, errorPath }
  webhook?: 回调模式（可选）
  cost:   { unit: second | call | point, price }（用于放行前估价）
}
```

- **请求模板**使用与厂商无关的变量：`{{prompt}} {{negative}} {{first_frame}} {{last_frame}} {{duration}} {{ratio}} {{resolution}} {{seed}} {{model}}`，响应用 JSONPath 提取任务号、状态、结果地址。
- **与厂商无关的镜头参数**：分镜节点输出的镜头（画面描述、首/尾帧、秒数、画幅）是中立的。适配层按 `capabilities` 做协商：时长取最近的支持值（超长镜头自动拆段）、有尾帧且支持首尾帧则用首尾帧、否则退回图生视频、再不行退回文生视频。
- **三种配置方式**：① 内置预设（选厂商 → 填 Key）；② 手工填写声明；③ **粘贴官方 curl 示例或文档片段，由 DeepSeek 起草声明**，再用「试一条」真实跑一次校验，通过才可保存。
- **安全**：沿用 `safeFetch`（禁止内网地址）、密钥服务端加密、成员不可见；模板只做字符串/JSON 替换，不执行任何用户代码。
- **逃生口**：个别接口流程特殊（多步上传、非标准签名）时，可在服务端以「适配插件」文件扩展，对用户仍表现为同一种凭据。
- 图像（定妆照、场景图）、配音（TTS）使用同一套声明机制，只是 `kind` 与参数不同。

### 6.3 配音
- 视频必须带配音。分镜已为每个镜头保留 `dialogue.speaker / emotion` 与 `narration`，人物库里每个角色有「声线」描述。
- P4 为每个角色指定一个 TTS 音色（可试听），按镜头生成台词与旁白音频；对本身带音频的视频模型（`audio: native`）则让用户选择「模型出声」或「TTS 覆盖」。
- 成片阶段用 ffmpeg 按时间线混音、烧录字幕、统一响度。

### 6.4 产物存储（本地磁盘）
- 视频、图片、音频直接存在服务器本地磁盘：`STORAGE_DIR`（默认 `./data/media`），目录 `{org}/{drama}/{node}/{asset}`；数据库只存元数据。
- 厂商返回的临时链接**生成完成后立即下载转存**；通过带鉴权的 `/api/media/:id` 提供访问（支持 Range 以便拖动播放）。
- 提供清理与容量提示；以后需要时再接入 S3 兼容存储，只需替换存储实现。

### 6.5 成本控制
放行前显示估价（镜头数 × 单价）；团队月度额度同时覆盖金额/点数；失败不重复计费并记录；全局并发上限；运行中可随时取消。

## 7. 技术方案

**数据模型**（新增迁移 `002_drama.sql`，同样受行级安全约束）

- `drama_projects`：关联 `project_id`（小说）、剧型预设、状态。
- `drama_nodes`：id、project、type、位置(x,y)、参数(jsonb)、状态、`input_hash`（判断是否过期）、`output`（jsonb/资产引用）、版本。
- `drama_edges`：from、to、端口。
- `drama_assets`：图片/视频/音频的元数据与存储键。
- `drama_runs`：执行记录（耗时、用量、费用、错误）。

**执行引擎**（服务端）

- 拓扑排序 + 按 `input_hash` 缓存：输入没变就不重跑。
- 文本节点：同步流式；媒体节点：入队 → worker 提交供应商 → 轮询 → 转存 → 事件推送（复用现有 SSE）。
- 幂等与断点续跑；失败节点单独重试；整体取消。
- 权限：沿用角色体系——作者可跑文本、编辑可放行视频花费、只读可看。章节锁思路扩展到"节点锁"，避免多人同时改同一集。

**前端**

- 画布：自研轻量实现（SVG 连线 + 绝对定位节点 + 视口变换），或引入 React Flow（xyflow）。**建议用 React Flow**：虚拟化、小地图、框选已成熟，把精力留给领域节点。
- 页面：作品内新增"短剧"栏目（与概览/设定集/大纲并列）；检查器复用现有面板风格。
- 时间线预览：浏览器内 `<video>` 串播 + 字幕叠加；最终合成在服务端用 ffmpeg。

## 8. 分期交付

| 阶段 | 内容 | 价值 |
| --- | --- | --- |
| **P1 文本管线** | 画布骨架 + ①②③④节点 + DeepSeek + 溯源 + 导出分镜 PDF/剧本 | 无需任何视频模型即可交付"可拍摄的剧本与分镜"，立即可用 |
| **P2 视觉资产** | 角色/场景图像节点 + 一致性圣经 + 资产库 | 定妆照与概念图 |
| **P3 视频生成** | 视频适配器 + 任务队列 + 估价放行 + 抽卡 | 核心卖点 |
| **P4 成片** | TTS 配音、字幕、时间线、ffmpeg 合成、MP4/剪映草稿导出 | 完整闭环 |
| **P5 打磨** | 一致性检查、模板市场（剧型预设分享）、协作评论 | 差异化 |

## 9. 已确定的决定

1. **视频模型**：不绑定某一家，采用 6.2 的声明式通用适配器；首批内置预设待你指定想优先的厂商。
2. **产物存储**：本地磁盘（6.4）。
3. **配音**：必须有（6.3），列入视频阶段交付。
4. **画布库**：React Flow（`@xyflow/react`）。
5. 画幅与时长默认：竖屏 9:16、每集 90 秒，均可在画布里改。
