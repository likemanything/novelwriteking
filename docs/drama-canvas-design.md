# 墨织「小说 → 短剧」画布：产品设计

> 一部小说进去，一部可以发布的竖屏短剧出来。画布不是让用户从零搭管线，而是**一条开箱即用、每一步都可展开、可改、可重跑的流水线**。

## 1. 定位：为什么不是又一个 ComfyUI

通用节点画布给的是「零件」，用户要自己知道该连什么。墨织的画布给的是**答案**：

| 通用画布 | 墨织短剧画布 |
| --- | --- |
| 空白画布 + 节点库 | 导入小说即自动生成整张工作流，用户从"看结果"开始 |
| 节点是技术概念（采样器、VAE） | 节点是编剧/导演概念（分集、场景、分镜、角色定妆、配音） |
| 连线决定数据类型 | 连线表示"这一步的产出喂给下一步"，类型由系统保证，不会连错 |
| 出错看日志 | 每个节点能说清"我用了小说第几章哪几段、为什么这样改" |
| 一次性跑完 | 逐节点审批：AI 提议、作者确认，与墨织"作者把关"一脉相承 |

核心原则：**一致性第一**（人物脸、服装、场景跨镜头不漂移）、**成本可见**（跑之前先估价）、**可断点续跑**（视频生成慢且贵，失败不重来）。

## 2. 用户旅程

1. **选小说**：书架上任意一部（自己写的、平台生成的、导入的 .txt）。选章节范围。
2. **选剧型**：一句话预设——集数（20–80 集）、单集时长（60–120 秒）、画幅（9:16 / 16:9）、类型节奏（爽文反转 / 悬疑 / 甜宠 / 古风）、画风（真人感 / 国风动画 / 2D 漫画）。
3. **一键生成工作流**：画布自动铺开整条流水线，文本类节点（改编、剧本、分镜）用 DeepSeek 立即跑完；用户在**剧本阶段先审**，满意再放行视频生成。
4. **审与改**：点任意节点展开右侧检查器，改文字、换图、锁定、重跑单个节点；改动自动让下游标记"已过期"。
5. **估价与放行**：视频生成前弹出清单（镜头数 × 单价 = 预计费用），确认才开始。
6. **成片**：时间线预览，换镜头、调配音、导出 MP4 / 剪映草稿 / 分镜 PDF。

## 3. 流水线（默认工作流）

```
小说章节 ─▶ ① 故事拆解 ─▶ ② 分集大纲 ─▶ ③ 单集剧本 ─▶ ④ 分镜脚本 ─▶ ⑤ 镜头视频 ─▶ ⑥ 成片
              │                              ▲              ▲              ▲
              ▼                              │              │              │
         人物库/场景库 ─▶ ⑦ 角色定妆照 ─▶ 场景概念图 ───────┴──────────────┘
                                  配音/字幕/音乐 ─────────────────────────────▶
```

| 节点 | 输入 | 输出 | 模型 |
| --- | --- | --- | --- |
| ① 故事拆解 | 小说章节 + 设定集 | 主线/支线、关键事件、人物关系、"可视化程度"打分 | 文本（DeepSeek） |
| ② 分集大纲 | 拆解结果 + 剧型 | 每集：钩子、冲突、反转、**结尾悬念**（短剧生命线）、对应原著章节 | 文本 |
| ③ 单集剧本 | 分集大纲 + 人物声线 | 场景化剧本：对白精简、动作可拍、旁白可选 | 文本 |
| ④ 分镜脚本 | 剧本 | 镜头列表：景别、运镜、时长(3–8s)、画面描述、台词、首尾帧提示词 | 文本 |
| ⑦ 角色定妆 / 场景概念 | 人物设定 + 画风 | 每个角色的标准形象（正/侧/全身）、每个主场景一张定调图 | 图像模型 |
| ⑤ 镜头视频 | 分镜 + 角色/场景参考图 | 每镜头一段视频（图生视频，首帧 = 参考图拼合） | 视频模型 |
| ⑥ 成片 | 镜头视频 + 配音 + 字幕 | 单集时间线 → MP4 | 配音(TTS) + 本地合成 |

**节点分组**：画布按"集"折叠成泳道，一眼看到整部剧的进度；"人物库/场景库"是跨集共享的**资产节点**，改一次全剧生效。

## 4. 画布交互

- **无限画布**：缩放/平移，小地图；自动布局（默认从左到右、按集分行），用户可拖动但不必。
- **节点状态**（颜色 + 印章语言，延续墨织视觉）：待办、运行中（丝线流动）、待审、已通过（朱砂印）、过期（淡出虚线）、失败（可重试）。
- **连线即依赖**：改上游 → 下游自动"过期"，一键"重算过期节点"，只跑变化的部分。
- **逐节点审批**：文本节点可"自动通过"，视频节点默认"需确认"。
- **溯源**：剧本里每句旁标注"来自第 12 章 ¶3"，点击跳回小说原文——这是相对通用工具的差异化能力。
- **版本**：每个节点保留历史输出，可回退、可 A/B 对比（尤其是视频抽卡）。
- **高级模式**（默认隐藏）：允许插入自定义节点（提示词节点、人工上传节点、条件分支），给进阶用户留出 ComfyUI 式自由。

## 5. 一致性方案（质量成败所在）

1. **角色圣经**：定妆照 + 固定外观描述词，作为每个镜头的强制参考输入。
2. **场景圣经**：每个主场景一张定调图 + 光线/色调描述。
3. **画风锁**：全剧统一风格词与负面词，写入每个镜头提示词。
4. **首尾帧衔接**：相邻镜头用上一镜尾帧作下一镜首帧（视频模型支持时）。
5. **抽卡与锁定**：每镜头默认生成 1 条，可"再来 N 条"择优，选定即锁定。
6. **一致性检查节点**（后期）：用视觉模型比对镜头与定妆照，低分镜头提示重做。

## 6. 模型接入与成本

- **文本**：复用墨织现有"AI 网关"（已支持 DeepSeek / OpenAI 兼容 / Anthropic），新增环节 `drama`（可与 `plan/write` 分配不同模型）。
- **图像、视频、配音**：新增三类凭据（`image` / `video` / `tts`），沿用密钥服务端加密、成员不可见、按成员记用量。视频与图像通常是**异步任务**（提交 → 轮询/回调），因此需要后端任务队列。
- **适配器接口**：`submit(job) → taskId`、`poll(taskId) → status/url`、`estimate(job) → 费用`。首批适配 1–2 家国内主流视频模型（具体厂商与接口需你确认，我会按其官方文档实现，不凭记忆写）。
- **成本控制**：放行前显示估价；团队月度额度同时覆盖"金额/点数"；失败自动退点记录；全局并发上限。
- **产物存储**：视频/图片落对象存储（本地磁盘 → S3 兼容），数据库只存元数据与链接；供应商临时链接须及时转存。

## 7. 技术方案

**数据模型**（新增迁移 `002_drama.sql`，同样受行级安全约束）

- `drama_projects`：关联 `project_id`（小说）、剧型预设、状态。
- `drama_nodes`：id、project、type、位置(x,y)、参数(jsonb)、状态、`input_hash`（判断是否过期）、`output`（jsonb/资产引用）、版本。
- `drama_edges`：from、to、端口。
- `drama_assets`：图片/视频/音频的元数据与存储键。
- `drama_runs`：执行记录（耗时、用量、费用、错误）。

**执行引擎**（服务端）

- 拓扑排序 + 按 `input_hash` 缓存：输入没变就不重跑。
- 文本节点：同步流式；媒体节点：入队 → worker 提交供应商 → 轮询 → 转存 → 事件推送（复用现有 SSE）。
- 幂等与断点续跑；失败节点单独重试；整体取消。
- 权限：沿用角色体系——作者可跑文本、编辑可放行视频花费、只读可看。章节锁思路扩展到"节点锁"，避免多人同时改同一集。

**前端**

- 画布：自研轻量实现（SVG 连线 + 绝对定位节点 + 视口变换），或引入 React Flow（xyflow）。**建议用 React Flow**：虚拟化、小地图、框选已成熟，把精力留给领域节点。
- 页面：作品内新增"短剧"栏目（与概览/设定集/大纲并列）；检查器复用现有面板风格。
- 时间线预览：浏览器内 `<video>` 串播 + 字幕叠加；最终合成在服务端用 ffmpeg。
