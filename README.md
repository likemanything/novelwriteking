# 墨织 Inkloom

> 把一句灵感，写成一部长篇。

墨织是一款面向个人与团队的 AI 长篇小说创作工具。先定人物、世界观和大纲，再一章一章写、审、改；AI 负责起草，每一处改动都由作者决定。

```bash
brew install postgresql@16   # 需要本机有 Postgres（仅开发环境用）
npm install
npm run setup                # 生成 .env（随机密钥）→ 启动开发数据库 → 迁移
npm run dev                  # 开发：http://127.0.0.1:5173（接口 4318 + 前端 5173）
```

开发环境的短信是「控制台模式」：登录页会直接显示验证码。`.env` 里的 `ADMIN_PHONES` 号码可以不用邀请码注册；之后在「团队管理」里生成内测邀请码、新建团队、邀请成员。
首次登录会在个人空间放上一部示例作品《雾港邮差》（2 章定稿、1 章待修订、3 条待确认的设定变化），不配置任何模型也能用内置的**离线演示引擎**走完全部流程。

生产部署见文末「部署」。

## 设计理念

受 [AI-Novel-Writer](https://github.com/EthanYoQ/AI-Novel-Writer) 的「可控创作流程」思路启发，墨织从零设计、独立实现（未复用其代码）。我们想解决长篇 AI 写作的三个核心痛点：

| 痛点 | 墨织的回答 |
| --- | --- |
| **前后矛盾**：写到第 20 章，模型忘了第 3 章的伏笔 | **本章参考资料**：每次生成用了哪些设定和前文、为什么用、占多少 token，全部可见、可关、可调预算 |
| **擅改设定**：AI 悄悄改掉了人物设定 | **作者把关**：AI 只给建议和新版本，写进设定集的每一条都要作者确认；每条设定标注来源（作者 / AI 生成 / 从定稿整理） |
| **质量不透明**：不知道 AI 写得好不好、哪里没写到 | **结构化审稿**：逐条核对细纲里的情节点是否真正写出来，引文可一键定位原文，意见由作者勾选后才修改 |

### 视觉语言

- **日间与夜间**两套配色，全局叠加一层纸张纹理，屏幕有纸感而非塑料感。
- **朱砂印章**是品牌标识：Logo、定稿、采纳设定时的盖章动画都用 SVG 滤镜模拟印泥的毛边与斑驳。
- **传统中国色**色板（朱砂、靛青、石绿、藤黄、胭脂……），每条故事线、每个人物都有自己的标识色，贯穿大纲、故事线页面和参考资料。
- **线装书封面**：每本书由种子生成独一无二的布面纹样、竖排题签与四眼订线，悬停时有 3D 倾斜与光泽。

### 标志性交互

| 时刻 | 动效 |
| --- | --- |
| 首页输入灵感 | 背景彩线随打字加速；点「开始创作」时彩线向中心收拢 |
| 开书生成 | 七个步骤（书名→人物→世界观→故事线…）随模型流式输出逐一点亮 |
| 生成细纲 | 章节卡片随 JSON 流式解析一张张出现，而不是等全部结束 |
| 生成草稿 | 正文一字一字写在稿纸上，末尾一枚呼吸的朱砂点 |
| AI 改写 | 选中文字弹出改写气泡：扩写 / 精简 / 润色 / 展示 / 对白 / 换气氛 / 自定义 |
| 续写 | ⌘J 在光标处浮出淡色续写，Tab 接受、Esc 放弃、继续打字即消失 |
| 定稿 | 印章从空中落下压在纸上，印泥向外晕开 |
| 故事线 | 每条故事线在推进它的章节上打一个圆点，一眼看出哪条伏笔被冷落 |

所有动效尊重系统「减弱动态效果」，也可在设置里手动关闭。

## 创作流程

```
一句灵感 ──开书──▶ 人物 · 世界观 · 故事线 · 文风
                        │
                    生成大纲（按批次，可断续）
                        ▼
           ┌──── 章节细纲：目标 / 情节点 / 章末悬念 / 出场人物 / 故事线
           │            │ 组织本章参考资料
           │            ▼
           │   草稿 ──▶ 审稿 ──▶ 修订 ──▶ 定稿
           │                                │ 整理设定变化
           │                                ▼
           └──── 设定集 ◀── 作者确认 ◀── 设定更新（待确认项）
```

每章都走「细纲 → 草稿 → 审稿 → 修订 → 定稿」五步；定稿后，AI 从正文中整理章节摘要、前情提要、人物状态、新设定与故事线进展，作为待确认项等作者采纳。采纳后的设定会在下一章作为参考资料使用，形成闭环。

### 页面

| 页面 | 作用 |
| --- | --- |
| 书架 | 灵感输入、作品封面墙；导入已有稿件（.txt / .md，按「第X章」等标题自动分章，兼容 GBK）或墨织备份 |
| 开书 | 构思 → 生成 → 确认（挑书名、删人物、改梗概） |
| 概览 | 下一步建议、各章字数、写作日历、故事线进展 |
| 设定集 | 人物（含**角色访谈**：以人物口吻对话挖掘动机）、世界观、故事线、文风（可从范文提炼）、故事梗概 |
| 大纲 | 按卷分组的章节细纲，AI 批量生成，可排序；**批量写作**：一次起草 1–10 章，可选每章自动审稿并修订，可暂停 / 停止，某章失败即停，不会自动定稿 |
| 写作台 | 稿纸编辑器 + 进度条 + 侧栏（细纲 / 参考资料 / 审稿 / 版本对比）；专注模式 ⌘. |
| 故事线 | 故事线 × 章节、人物 × 章节的出场分布，附「结构提醒」 |
| 设定更新 | 定稿后整理出的设定变化：可修改后采纳、驳回、批量采纳 |
| 设置 | 模型接入、环节分工、写作偏好、数据备份与未能保存的修改 |
| 团队管理 | 成员与角色、邀请链接、AI 用量与额度、内测邀请码（平台管理员）|

## 模型

墨织不提供、不托管任何模型。**模型属于团队**，由管理员在「设置 → 接入模型」配置，成员直接使用：

- **DeepSeek**：只粘贴 API Key。地址与协议已预设，模型列表从接口自动读取。
- **通用接入**：填接口地址和 Key（本地模型可不填 Key），服务端自动完成四步：
  1. **规范地址**：补全 `https://`，去掉误粘的 `/chat/completions`、`/v1/messages` 等后缀；
  2. **识别协议**：依次探测 OpenAI 兼容、Anthropic、Ollama；
  3. **读取模型**：过滤掉向量、语音、图像模型，按写作场景挑一个默认模型；
  4. **试写一句**：发一次真实的流式对话，确认整条链路可用。

「构思 / 写作 / 审稿 / 改写」四个环节可分别指定模型。第一个接入的模型会自动负责全部四个环节。

**密钥与用量**：API Key 经 `MASTER_KEY` 加密后存在数据库里，**永远不会下发到浏览器**；所有模型请求都经服务端「AI 网关」转发（流式），网关负责权限检查、按成员/环节/模型记录用量、执行月度额度，并在用户点「停止」时同步取消上游请求。默认禁止把模型地址指向内网和云元数据地址（`ALLOW_PRIVATE_MODEL_HOSTS`）。

## 团队与权限

登录用手机号 + 短信验证码。每个用户有一个**个人空间**，也可以新建**团队**并邀请成员；每个空间有独立的作品、成员、模型与额度。

| 角色 | 能做什么 |
| --- | --- |
| 所有者 | 全部权限，包括删除团队、转让所有权 |
| 管理员 | 管理成员、模型接入、用量额度 |
| 编辑 | 管理作品与设定集，定稿、采纳设定变化 |
| 作者 | 写章节、改细纲、用 AI 起草与审稿；不能定稿、不能改设定集 |
| 只读 | 只能查看 |
| 外部协作者 | 只能访问被邀请的作品，并按授权的角色（编辑 / 作者 / 只读）行事 |

- **邀请**：管理员生成带角色、次数、有效期的邀请链接（`/invite/…`），对方登录后自动加入，无需内测邀请码。
- **章节锁**：同一章同一时间只有一个人能编辑。进入写作台自动加锁，别人在编辑时本机只读，对方离开后自动接手。
- **权限双重保障**：前端按角色隐藏或禁用操作，服务端用同一份规则（`src/shared/permissions.ts`）做最终裁决，数据库另有行级安全（RLS）隔离租户。
- **用量**：「团队管理」里按成员 / 环节 / 模型查看本月 token，管理员可设团队与个人月度上限。

## 技术架构

| 层 | 选型 |
| --- | --- |
| 界面 | React 19 · React Router 7 · Tailwind CSS 4 · Motion |
| 编辑器 | CodeMirror 6（流式写入、续写预览、引文定位均为自定义扩展） |
| 本地数据 | IndexedDB（Dexie + 实时查询）。每个「用户 × 团队」一个库，是云端数据的**离线副本** |
| 同步 | 本地写入被变更追踪，增量推送到服务端；服务端变更经 SSE 推回，断网时可继续写，联网后自动同步。被服务端拒绝的修改暂存在「设置 → 数据」里可找回 |
| 服务端 | Node 22 · Hono · Postgres（行级安全）· 阿里云短信（可选）|
| 状态 | Zustand（个人偏好存本机；模型与团队配置来自服务端）|

```
src/
  ai/        client 流式客户端（经 AI 网关）· detect 协议识别 · lens 参考资料组织 · prompts · tasks 高层任务 · demo 离线引擎
  cloud/     api 请求封装 · session 登录与团队 · sync 同步引擎 · locks 章节锁 · models 模型与环节
  lib/       types 领域模型 · db 本地数据库 · repo 设定写入 · export 导出与备份 · importText 稿件导入 · sample 示例作品
  shared/    permissions 角色与权限规则 · api 前后端共用的接口类型
  store/     settings 个人偏好 · jobs 后台任务 · batch 批量写作 · ui 通知与面板
  studio/    Editor · LensPanel · CritiquePanel · VersionsPanel · MuseBubble · PipelineRail · diff
  pages/     Login · Invite · Library · Genesis · Overview · Bible · Outline · Studio · Loom · Inbox · Settings · Team
  components/ 设计系统基元、印章、封面、背景动画、命令面板、账号菜单、模型接入
server/      app 路由装配 · auth 登录 · orgs 团队与邀请 · sync 同步与章节锁 · ai 模型接入与网关 · admin 内测邀请码 · db 迁移
tests/       api.test.ts 服务端接口测试（npm run test:api）
```

关键设计决策：

- **永不丢稿**：AI 生成被中断或出错时，只要已有正文就保存为版本；对 AI 稿或定稿的第一次手改会分叉出新版本，原稿保留可对比。
- **建议而非直写**：定稿后整理出的设定变化进入 `proposals` 表，只有作者采纳才会修改人物、世界观、故事线与前情提要。
- **参考资料优先级**：本章细纲（必用）> 文风 > 上章结尾 > 出场人物 > 前情提要 > 最近章节 > 故事线 > 关键词命中的世界观条目 > 故事梗概 > 更早章节摘要；按预算取用，细纲放在最后、离生成位置最近。
- **稳健解析**：结构化输出兼容代码块、前后缀废话、尾逗号；大纲用增量 JSON 数组解析实现流式卡片。

## 部署

1. 准备 Postgres（应用账号**不能是超级用户**，否则行级安全失效；启动时会检查）。
2. 复制 `.env.example` 为 `.env`，填写必填项：`NODE_ENV=production`、`PUBLIC_URL`、`DATABASE_URL`、`SESSION_SECRET`（≥32 随机字符）、`MASTER_KEY`（`openssl rand -base64 32`，**丢失后已保存的模型密钥无法解密**）、`ADMIN_PHONES`，以及 `SMS_PROVIDER=aliyun` 和对应的短信密钥。
3. `npm install && npm run build && npm start`，数据库迁移在启动时自动执行（也可 `npm run migrate`）。
4. 放在 Nginx 等反向代理之后并启用 HTTPS，设 `TRUST_PROXY=true`；反向代理需关闭对 `/api/sync/events`（SSE）的缓冲。

运维命令：

```bash
npm run admin -- code 5 1 内测批次   # 生成 5 个一次性内测邀请码
npm run admin -- codes               # 查看邀请码
npm run admin -- make-admin 手机号    # 设为平台管理员
npm run admin -- disable 手机号       # 停用账号并让其退出所有设备
```

## 数据与安全

- 作品保存在服务端数据库，并在浏览器里留有离线副本。**退出登录会清除本机副本**（会先尽力同步未上传的修改，失败时给出提示）。仍建议定期「备份全部作品」（设置页）。
- 模型 API Key 加密保存在服务端，不下发给任何成员。
- 写请求校验来源（防 CSRF）；验证码、邀请、识别等接口有频率限制；模型地址默认禁止指向内网。
